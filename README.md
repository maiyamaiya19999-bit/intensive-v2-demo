# Кабинет интенсива · как им пользоваться

Это личный кабинет ученицы: анкета → модули-«сотрудники» → шаги → задания. Главная механика — кнопка **«Скопировать моё сообщение»**: кабинет сам подставляет в готовое сообщение для нейросети тексты, которые ученица сдала (распаковка, аудитория, продукт, оффер), её имя и нишу.

Без сборщиков и фреймворков: обычные HTML/CSS/JS. Править можно в любом текстовом редакторе.

---

## 1. Посмотреть прямо сейчас (демо, без ключей)

Два варианта:

- **Двойной клик по `старт.command`** — откроется браузер с кабинетом в демо-режиме. Всё хранится в браузере, ничего никуда не отправляется.
- Или открой `index.html` двойным кликом. Тоже работает (из копии контента `content/inline.js`, см. раздел «Как обновлять контент»).

В демо справа вверху есть кнопка **«Демо»** — панель, где можно переключать тариф, маршрут, «сдать» задания одним кликом, включить «14 дней без сдач» и «доступ истёк». Кнопка «Сбросить демо» стирает всё.

Адрес демо-режима на сайте: `…/index.html?demo=1` — работает и когда ключи Supabase уже вставлены.

## 2. Что завести (один раз)

### Supabase — база, вход по письму, файлы
1. Зарегистрируйся на supabase.com, создай проект (регион любой, ближе к Европе).
2. **SQL Editor** → вставь целиком файл `supabase/schema.sql` → Run. Это создаст таблицы, права и папку для файлов.
3. **Authentication → Providers → Email**: включи, выключи «Confirm email» не нужно (ссылка для входа и так подтверждает). «Enable email signups» можно выключить — ученицы появляются только через оплату.
4. **Authentication → URL Configuration**: в «Site URL» и «Redirect URLs» добавь адрес кабинета (например `https://maysoulme.ru/kabinet/`).
5. **Project Settings → API**: скопируй `Project URL` и `anon public` ключ → вставь в `config.js`:
   ```js
   SUPABASE_URL: "https://xxxx.supabase.co",
   SUPABASE_ANON_KEY: "eyJ...",
   APP_URL: "https://maysoulme.ru/kabinet/",
   ```
   Это публичные ключи, их можно хранить в коде. `service_role` ключ в код НЕ вставлять никогда.

### Продамус — оплата создаёт ученицу
1. В настройках формы оплаты в Продамус укажи **URL уведомлений**: `https://xxxx.supabase.co/functions/v1/prodamus-webhook`.
2. Там же возьми **секретный ключ** формы.
3. На компьютере с Supabase CLI (это один раз, можно попросить помочь):
   ```
   supabase login
   supabase link --project-ref xxxx
   supabase secrets set PRODAMUS_SECRET=... APP_URL=https://maysoulme.ru/kabinet/
   supabase functions deploy prodamus-webhook --no-verify-jwt
   supabase functions deploy daily-reminder
   ```
4. Тариф определяется по сумме оплаты: 4 990 → «Растущий блог», 6 990 → «Блог как бизнес», 89 990 → VIP, 2 000 → доплата до «Блог как бизнес». Если цены поменяются — задай секрет `TARIFF_MAP`, например `{"5990":"grow","7990":"money"}`.
5. Сделай тестовую оплату и проверь в Supabase → Table Editor → `users_profile`, что ученица появилась, а на почту пришло письмо со ссылкой. Если в логах функции «bad signature» — проверка подписи Продамус отличается от описанной, надо поправить функцию `verify` в `supabase/functions/prodamus-webhook/index.ts`.

### Ежедневная проверка «14 дней без сдач»
Функция `daily-reminder` раз в день смотрит, кто две недели ничего не сдавал: открывает все шаги, продлевает доступ на 14 дней и шлёт напоминание. Сейчас напоминание пишется в лог (а при `REMINDER_CHANNEL=telegram` и заданных `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ADMIN_CHAT_ID` — приходит тебе в Telegram). Канал для учениц (письмо / бот) ещё надо выбрать.

Расписание: Supabase → **Database → Cron** (или SQL Editor):
```sql
select cron.schedule('daily-reminder', '0 7 * * *', $$
  select net.http_post(
    url := 'https://xxxx.supabase.co/functions/v1/daily-reminder',
    headers := '{"Authorization": "Bearer <SERVICE_ROLE_KEY>"}'::jsonb)
$$);
```

### Kinescope — видео
Загрузи видео в Kinescope, в настройках защиты разреши домен кабинета. У каждого видео есть id (в ссылке `kinescope.io/embed/<id>` или `kinescope.io/<id>`). Вставь его в `content/program.json` → нужный шаг → `"video": { "kinescope_id": "здесь id" }`. Пока id пустой, на месте видео серый прямоугольник.

## 3. Выложить на GitHub Pages

1. Создай репозиторий (например `kabinet`) в аккаунте maiyamaiya19999-bit, положи в него всю папку `платформа` (содержимое, не саму папку). Файл `.nojekyll` уже есть — он нужен.
2. Settings → Pages → Source: `main`, папка `/ (root)`.
3. Через минуту кабинет откроется на `https://maiyamaiya19999-bit.github.io/kabinet/`. Этот адрес и укажи в `config.js` → `APP_URL` и в Supabase → Redirect URLs.
4. Если подключаешь свой домен (maysoulme.ru/kabinet) — как с другими гайдами.

Папку `supabase/` можно не выкладывать на Pages, она нужна только для настройки.

## 4. Как обновлять контент

Весь контент лежит в `content/`:

- **`program.json`** — модули и шаги. Каждый шаг: название, результат, формат (video / audio / text / guide), минуты, записка «от Майи», список «что сделать», «как понять, что получилось», файлы, задание, видео, ассистент, скилл, пути А/Б. В начале файла есть подсказка по полям. Чтобы добавить файл к шагу — впиши ссылку в `"url"`. Пустая ссылка показывается как «скоро».
- **`assistants/*.md`** — тексты ассистентов (готовые сообщения для нейросети). Внутри плейсхолдеры, которые кабинет заменяет сам:
  `{{РАСПАКОВКА}}`, `{{АУДИТОРИЯ}}`, `{{ПРОДУКТ}}`, `{{ОФФЕР}}` — сданные тексты; `{{ИМЯ}}`, `{{НИША}}` — из анкеты; `{{ПРАВИЛА_ПИСЬМА}}` — файл `00_правила_письма.md` (с заголовка «## Правила письма» до конца). В буфер из файла ассистента попадает только часть после «## Готовое сообщение»; блок «Как пользоваться» дублируется в поле `assistant_howto` шага.
  Какой ассистент к какому шагу — поле `"assistant"` в `program.json` (имя файла без `.md`).
- Фото модулей — `assets/img/*.jpg`, у модуля поле `"img": "h"`. Чтобы поменять фото, положи новый jpg и укажи его имя.

После правок: проверь JSON (например на jsonlint.com — одна лишняя запятая ломает всё; кабинет тогда покажет ошибку с номером строки) и выложи на GitHub.

Если открываешь кабинет двойным кликом по `index.html` (а не через `старт.command` или сайт) — после правок запусти `tools/обновить-контент.command`, он пересоберёт копию `content/inline.js`. На сайте этот файл не нужен, там читаются настоящие `program.json` и `.md`.

## 5. Правила, которые зашиты в кабинет

- **Тарифы**: «Растущий блог» — 45 дней, все модули кроме 5 и 10 (в модуле 3 только шаг 3.3), поменять задание можно 1 раз. «Блог как бизнес» — 180 дней, все модули, 2 правки. VIP — 365 дней, без замков.
- **Замки** на 6 заданиях: распаковка (2.1), аудитория (2.2), продукт (3.1), оффер (3.2), позиционирование (3.3), план бесплатного урока (5.1). Шаги после несданного замка закрыты.
- **Автооткрытие**: 14 дней без сдач → всё открыто, доступ +14 дней (серверная функция; в кабинете это же правило дублируется, чтобы демо работало).
- **Срок доступа** вышел → кабинет только для чтения, файлы остаются.
- **Варианты шага по нейросети**: в анкете ученица выбирает Claude / ChatGPT / нет аккаунта, и шаг 1.1 показывает свой вариант (поле `variants`).
- **Пути А/Б**: шаги с автоматизацией показывают две вкладки — компьютер (Claude Code) и телефон. По умолчанию открыта та, что соответствует ответу анкеты про компьютер.

Все числа (дни, правки, цены) — в `content/program.json` → `tariffs`, `auto_open_days`, `auto_extend_days`.

## 6. Структура папки

```
платформа/
  index.html            — каркас страницы
  config.js             — КЛЮЧИ И ССЫЛКИ (единственное, что надо заполнить)
  старт.command         — открыть демо двойным кликом
  css/style.css         — стиль (из макета)
  js/                   — логика: icons, content, store (демо/Supabase), access (права), prompt (копирование), screens, app
  content/
    program.json        — программа
    assistants/*.md     — ассистенты
    inline.js           — автокопия для открытия двойным кликом (собирает tools/обновить-контент.command)
  assets/               — фото, логотип, иконки, рукописный шрифт
  supabase/
    schema.sql          — база данных
    functions/prodamus-webhook/   — оплата → ученица → письмо
    functions/daily-reminder/     — 14 дней без сдач
  tools/                — служебные скрипты
```
